# VKApp — учебное iOS-приложение социальной сети

**VKApp** — учебное iOS-приложение, имитирующее функциональность социальной сети, разработанное на языке Swift с использованием UIKit и полностью программной вёрстки интерфейса.

Приложение реализует основные возможности социальной сети: ленту публикаций, истории, друзей, фотографии, поиск, сообщения, короткие видео (Reels), создание контента, поиск и прослушивание музыки, добавление фильмов, локализацию и поддержку светлой и тёмной тем оформления.

Проект разработан в рамках обучения iOS-разработке и демонстрирует применение современных архитектурных подходов, работу с локальным хранилищем, сетевыми API, мультимедиа и адаптивными интерфейсами.

---

## 1. Технологии

- **Swift 6** — основной язык программирования.
- **UIKit** — создание пользовательского интерфейса.
- **Programmatic UI** — интерфейс полностью реализован программно, без Storyboard.
- **Auto Layout** — адаптивная вёрстка для iPhone и iPad.
- **Core Data** — локальное хранение данных.
- **AVFoundation / AVKit** — воспроизведение аудио и видео.
- **PhotosUI** — выбор фотографий и видео из медиатеки устройства.
- **URLSession / async-await** — выполнение сетевых запросов.
- **Codable** — декодирование данных из JSON.
- **MVVM** — разделение представления и бизнес-логики.
- **Coordinator** — управление навигацией.
- **Repository Pattern** — абстракция доступа к данным.
- **Dependency Injection** — управление зависимостями.
- **Localization** — поддержка нескольких языков интерфейса.
- **Dynamic Appearance** — поддержка светлой и тёмной тем.

### Используемые внешние API

- **iTunes Search API** — поиск музыкальных композиций, получение обложек и предварительное прослушивание.
- **TVMaze API** — поиск фильмов и сериалов, получение постеров, названий и описаний.
- **Audius API** — интеграция поиска и потокового воспроизведения музыкальных треков.

## 2. Системные требования

- Xcode 26 или новее.
- Swift 6.
- iOS 17.0 или новее.
- iPhone или iPad.

Приложение тестировалось на симуляторах:

- iPhone 17 Pro.
- iPad Air 13” (M4).

Поддерживаются портретная и альбомная ориентации с адаптацией интерфейса под размер устройства.

## 3. Возможности приложения

### 3.1. Авторизация

- Стартовый экран приложения.
- Вход по номеру телефона.
- Сохранение пользовательской сессии.
- Автоматический вход после повторного запуска приложения.
- Выход из аккаунта.

Авторизация реализована локально, без подключения к серверу.

### 3.2. Главная лента

- Отображение списка публикаций.
- Текстовые публикации.
- Публикации с изображениями.
- Видеопубликации.
- Воспроизведение видео.
- Музыкальные публикации с обложкой, названием композиции и исполнителем.
- Прослушивание музыкальных композиций через интегрированные музыкальные сервисы.
- Публикации с фильмами и сериалами, включая постер, название и описание.
- Горизонтальный список историй.
- Лайки с изменением количества при действиях пользователя.
- Переход на профиль автора.

**Текущие ограничения ленты:**

- Комментарии, репосты и просмотры отображаются, но не имеют полноценной интерактивной реализации.
- Раскрытие полного текста публикации не реализовано.

### 3.3. Истории (Stories)

- Горизонтальный список историй.
- Круглые миниатюры историй.
- Просмотр истории.
- Создание новой истории.
- Выбор изображений из медиатеки.
- Локальное хранение изображений.
- Сохранение метаданных в Core Data.

### 3.4. Друзья

- Список друзей.
- Отображение аватаров.
- Отображение информации о пользователях.
- Навигация к экрану пользователя.

Полноценный функционал редактирования профиля не реализован.

### 3.5. Фотографии

- Отображение фотографий в виде сетки.
- Адаптивное количество колонок.
- Поддержка разных размеров iPhone и iPad.
- Просмотр выбранной фотографии.
- Использование Auto Layout для адаптации интерфейса.

### 3.6. Поиск

Реализован поиск различных типов контента:

- Пользователей.
- Сообществ.
- Рекомендованного контента.
- Музыкальных композиций.
- Фильмов и сериалов.

Поиск музыки и фильмов выполняется через внешние API.

Для результатов поиска используются адаптивные интерфейсы, учитывающие размер экрана устройства.

### 3.7. Мессенджер

- Список диалогов.
- Экран переписки.
- Отображение входящих и исходящих сообщений.
- Отправка локальных текстовых сообщений.
- Различное оформление сообщений отправителя и получателя.
- Сохранение сообщений в Core Data.
- Поддержка светлой и тёмной тем оформления.

Обмен сообщениями между реальными пользователями через сервер не реализован.

### 3.8. Reels — короткие видео

- Вертикальная лента коротких видеороликов.
- Воспроизведение текущего ролика.
- Автоматическая остановка предыдущего видео при переключении.
- Поддержка локальных и встроенных видеороликов.
- Отображение лайков, комментариев и просмотров.
- Создание собственных клипов.
- Сохранение видео в локальное хранилище приложения.

### 3.9. Музыка

В приложение добавлена интеграция музыкальных сервисов.

Возможности:

- Поиск композиций по названию и исполнителю.
- Получение результатов поиска через музыкальные API.
- Отображение названия композиции и исполнителя.
- Загрузка и отображение обложек альбомов.
- Предварительное прослушивание через iTunes.
- Интеграция Audius для потокового воспроизведения доступных треков.
- Создание музыкальной публикации.
- Отображение музыкального контента в главной ленте.

Доступность полного воспроизведения зависит от выбранного музыкального сервиса и конкретной композиции.

### 3.10. Фильмы и сериалы

Добавлена интеграция **TVMaze API**.

Возможности:

- Поиск фильмов и сериалов по названию.
- Получение данных из внешнего API.
- Отображение названия произведения.
- Загрузка постера.
- Отображение описания и дополнительной информации.
- Выбор фильма или сериала для публикации.
- Создание публикации с постером и описанием.
- Сохранение метаданных публикации в Core Data.
- Отображение публикаций в главной ленте.

TVMaze используется как источник информации о фильмах и сериалах, а не как сервис их воспроизведения.

### 3.11. Создание контента

В приложении поддерживается создание:

- Текстовых публикаций.
- Публикаций с фотографиями.
- Видеопубликаций.
- Историй.
- Коротких видео (клипов).
- Музыкальных публикаций.
- Публикаций с фильмами и сериалами.

Изображения и видео копируются в локальное файловое хранилище приложения.

Метаданные публикаций сохраняются в Core Data.

Для внешнего контента дополнительно сохраняются идентификаторы, названия, описания, URL изображений и медиаресурсов.

### 3.12. Локализация

В приложении реализована поддержка локализации пользовательского интерфейса (на данном этапе только русский и английский языки).

- Использование локализованных строк вместо жёстко заданного текста.
- Централизованное получение переводов.
- Локализация заголовков экранов.
- Локализация кнопок, подписей и системных сообщений приложения.
- Возможность добавления новых языков без изменения основной логики приложения.

Локализация реализована средствами iOS и Foundation.

### 3.13. Светлая и тёмная темы

Приложение поддерживает два варианта оформления:

- **Light Mode** — светлая тема.
- **Dark Mode** — тёмная тема.

Реализованы:

- Использование динамических системных цветов UIKit.
- Централизованное управление цветами через `AppColors`.
- Адаптация фона, текста, карточек и элементов интерфейса.
- Обновление оформления при изменении системной темы.
- Использование современных API отслеживания изменений `UITraitCollection`.

Для отслеживания изменений темы используется `registerForTraitChanges`, доступный начиная с iOS 17.

## 4. Архитектура приложения

Проект построен с использованием нескольких архитектурных подходов.

### 4.1. MVVM

**Model–View–ViewModel** разделяет интерфейс и логику приложения.

- **Model** — структуры данных и сущности Core Data.
- **View** — UIKit-компоненты пользовательского интерфейса.
- **ViewModel** — подготовка данных, обработка действий пользователя и взаимодействие с сервисами.

### 4.2. Repository Pattern

Работа с локальным хранилищем скрыта за протоколами репозиториев:

- `FeedRepository`
- `UserRepository`
- `PhotoRepository`
- `NotificationRepository`
- `MessengerRepository`
- `ReelRepository`
- `AuthenticationRepository`

Репозитории обеспечивают разделение бизнес-логики и реализации хранения данных.

### 4.3. Coordinator

Навигацией приложения управляет `AppCoordinator`.

Coordinator отвечает за запуск приложения, переходы между экранами и организацию пользовательских сценариев.

### 4.4. Dependency Injection

Зависимости создаются в `DependencyContainer` и передаются компонентам через инициализаторы.

Это уменьшает связанность компонентов и упрощает дальнейшее развитие приложения.

### 4.5. Network Layer

Для взаимодействия с внешними сервисами используется сетевой слой на основе `APIClient`.

Основные задачи:

- Выполнение HTTP-запросов.
- Асинхронное получение данных.
- Декодирование JSON.
- Обработка сетевых ошибок.
- Преобразование API-моделей во внутренние модели приложения.

Для работы с конкурентностью используются `async/await`, `Sendable` и механизмы изоляции Swift 6.

## 5. Хранение данных

Для локального хранения используется **Core Data**.

В базе сохраняются:

- Пользователи.
- Публикации.
- Истории.
- Фотографии.
- Уведомления.
- Диалоги.
- Сообщения.
- Reels.
- Метаданные музыкальных публикаций.
- Метаданные публикаций с фильмами и сериалами.

### Хранение медиаконтента

Изображения и видео сохраняются в файловой системе приложения.

В Core Data хранятся только имена локальных файлов и связанные метаданные.

Для внешнего медиаконтента используются URL-адреса ресурсов.

Такой подход позволяет не хранить большие медиафайлы непосредственно в базе данных.

VKApp поддерживает различные размеры экранов iPhone и iPad.

Реализованы:

- Программная вёрстка с Auto Layout.
- Адаптивные сетки фотографий.
- Динамическое количество колонок.
- Поддержка изменения ориентации устройства.
- Адаптация размеров элементов интерфейса.
- Поддержка светлой и тёмной тем.

Для вычисления параметров адаптивной сетки используется вспомогательный компонент `AdaptiveLayout`.

## 7. Ограничения текущей версии

VKApp является учебным проектом и не предназначен для использования в качестве полноценной социальной сети.

Текущие ограничения:

- Отсутствует серверная синхронизация пользовательских данных.
- Авторизация и пользовательские сессии реализованы локально.
- Нет полноценного обмена сообщениями между реальными пользователями.
- Отсутствуют удалённые push-уведомления.
- Нет полноценного редактирования профиля пользователя.
- Комментарии, репосты и просмотры в основной ленте не имеют полной функциональной реализации.
- Раскрытие полного текста публикаций не реализовано.
- Unit-тесты не добавлены.
- Загруженные пользователем изображения и видео хранятся локально.
- Доступность музыкального воспроизведения зависит от ограничений внешних API.
- Интеграция TVMaze предоставляет информацию о фильмах и сериалах, но не их воспроизведение.
